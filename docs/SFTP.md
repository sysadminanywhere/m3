# SFTP

Для источника и получателя типа `sftp` укажите абсолютный `settings.path`, `host`, `port`, `username`, `hostKeyFingerprint` в формате `SHA256:...` и `credentialRef` — ссылку на секрет. Отпечаток ключа сервера обязателен; его следует проверить по доверенному каналу до публикации. Указание самого пароля или ключа в конфигурации запрещено.

`settings.authMethod` принимает `PASSWORD` или `PRIVATE_KEY`; отсутствие поля означает `PASSWORD`, как в существующих конфигурациях. Для `PRIVATE_KEY` секрет содержит незашифрованный закрытый ключ OpenSSH. Защищённые паролем ключи пока не поддерживаются. `settings.credentialProvider` принимает `COMMUNITY` или `VAULT`; отсутствие поля означает `COMMUNITY` и сохраняет прежнее поведение. Значение секрета разрешается при каждом новом соединении, поэтому его можно заменить без публикации новой версии конфигурации. Проверяйте ротацию и подключение на конкретном сервере до использования в работе.

## HashiCorp Vault KV v2

Для `VAULT` укажите `credentialRef` в формате `mount/путь#поле`, например `secret/m3/sftp#private_key`. Mount — один сегмент, путь — один или более сегментов; допустимы латинские буквы, цифры, `_` и `-`. Поле KV v2 должно быть непустой строкой с ключом OpenSSH или паролем. Читается последняя версия: для примера используется Vault API `GET /v1/secret/data/m3/sftp`, поле `data.data.private_key`. Community не записывает и не администрирует секреты Vault.

Задайте Community `M3_VAULT_ADDR` (HTTPS с доверенным JVM сертификатом; HTTP разрешён только для loopback при локальной проверке) и `M3_VAULT_TOKEN_FILE` — путь к файлу с токеном, доступному процессу Community. При Compose путь относится к контейнеру: файл необходимо смонтировать отдельно с ограниченными правами, например как read-only secret. Переменные передаются в Community из обоих Compose-файлов. Рекомендуется Vault Agent с подходящим механизмом auto-auth и file sink; Community читает файл при каждом обращении, но сама не получает и не продлевает токен. Завёрнутые или зашифрованные sink-токены не поддерживаются. Выдайте токену только `read` на нужный путь KV v2, например `path "secret/data/m3/sftp" { capabilities = ["read"] }`. Политика, TLS и доступность конкретного Vault проверяются на целевой инфраструктуре. `M3_SECRET_KEY` по-прежнему нужен для используемых секретов Community; отказ Vault не переключает чтение на PostgreSQL.

`POST /api/v2/sftp/check` принимает `host`, `port`, `username`, `credentialRef`, `credentialProvider`, `hostKeyFingerprint`, `authMethod` и `path`. Проверка открывает SFTP с обязательной проверкой ключа сервера и запрашивает атрибуты каталога, не создавая файлов; успех не подтверждает право записи или возможность атомарного переименования. Endpoint защищён техническим токеном Community. В Enterprise проверка требует права изменения конфигурации и записывается в аудит. Значение секрета в запросе не передаётся.

При отправке применяется временное имя и удалённое переименование. Сервер и хранилище должны поддерживать подходящую семантику переименования. Если соединение оборвалось после начала публикации, результат может быть неопределённым: перед повтором проверьте получателя, поскольку повтор способен создать дубликат.

Источник проверяет размер и время изменения до и после копирования, а также размер копии. Изменение этих признаков во время чтения откладывает приём до повторного стабильного наблюдения. Эта проверка не гарантирует обнаружение изменения содержимого, если сервер сохранил тот же размер и время изменения; для надёжной передачи готовый файл следует размещать атомарным переименованием и больше не менять.

# Метрики Community

`GET /api/v2/metrics/prometheus` отдаёт текст Prometheus 0.0.4. Как и прочие внутренние API Community, этот путь защищается `M3_API_TOKEN`, если токен включён; используйте заголовок `X-M3-Service-Token` и защищённый сетевой канал. Не публикуйте endpoint непосредственно в интернет. Доступность самого скрейпа контролируется стандартной метрикой Prometheus `up`.

- `m3_jobs{status="..."}` — текущее число сохранённых заданий по состояниям READY, RETRY, RUNNING, UNCERTAIN и DELIVERED.
- `m3_jobs_delivered_last_hour` — число сохранённых заданий, завершившихся за последний час. Это gauge, а не монотонный счётчик: удаление записей и скользящее окно уменьшают значение.
- `m3_job_failure_events_last_hour{status="RETRY|UNCERTAIN"}` — число сохранённых записей истории с соответствующим состоянием за последний час, включая начальные записи истории. Одно задание может попасть в подсчёт несколько раз; удаление истории и скользящее окно уменьшают значение. Это gauge, а не счётчик всех ошибок сервиса.
- `m3_oldest_open_job_seconds` — возраст самого старого незавершённого задания; ноль означает отсутствие открытых заданий или возраст меньше точности измерения.
- `m3_storage_available` — удалось ли прочитать файловую систему настроенного каталога оригиналов на этом экземпляре. Если нет, метрики объёма отсутствуют, а не показывают ноль.
- `m3_storage_usable_bytes` и `m3_storage_total_bytes` — доступный процессу объём и ёмкость файловой системы этого экземпляра, а не точный размер M3 и не гарантия доступности общего хранилища с других узлов.

Значения заданий читаются из общей БД и одинаковы для реплик одного Community: при скрейпе нескольких реплик используйте, например, `max`, а не `sum`. Метрики файловой системы следует рассматривать по экземплярам. Данные являются снимком на момент скрейпа; недоступность БД приводит к ошибке скрейпа. Метрики не содержат имена файлов, адреса получателей или секреты.

Настройте оповещение по `up == 0` и разумный `scrape_timeout`: при зависшем соединении с БД ответ может задержаться до таймаута подключения приложения. Например, на локальном стенде при приостановке PostgreSQL запрос завершился HTTP 500 примерно через 30 секунд, после возобновления БД следующий скрейп вернул HTTP 200. Это время не является гарантией для всех сетевых отказов и настроек драйвера.

Пример Grafana-дашборда находится в `monitoring/m3-community-dashboard.json`: импортируйте его и выберите источник Prometheus. Панель доступности ожидает имя scrape job `m3-community`. При нескольких независимых установках добавьте в scrape-конфигурацию метку установки и ограничьте запросы ею: глобальный `max` в примере предполагает одну установку.

# HTTP-получатель

Получатель типа `http` задаётся полем `settings.url`: HTTPS без встроенных учётных данных, строки запроса и фрагмента. Для локальной проверки HTTP разрешён только на `localhost`, `127.0.0.1` или `::1`. Перенаправления и системный HTTP-прокси не используются; TLS-сертификат и имя сервера проверяются стандартными средствами Java. Доступность и доверие к сертификату конкретной инфраструктуры нужно проверить отдельно.

Необязательный `settings.tokenRef` ссылается на секрет Community с Bearer-токеном. Сам токен не включается в конфигурацию и запрашивается при каждой попытке. До отправки проверяются SHA-256 оригинала и аренда задания. Запрос — `POST` с исходными байтами, `Content-Type: application/octet-stream` и стабильным идентификатором задания в `Idempotency-Key`.

Перед отправкой создаётся временная копия оригинала в системном каталоге временных файлов процесса Java; этому каталогу нужны достаточный объём и ограниченный доступ. При обычном завершении попытки копия удаляется. При аварийном завершении процесса она может остаться и потребовать безопасной очистки оператором.

Любой HTTP 2xx подтверждает только приём сервером; бизнес-обработка не гарантирована. Ошибка до начала запроса приводит к обычному повтору. После начала запроса потеря ответа, ошибка соединения или ответ вне диапазона 2xx дают `UNCERTAIN`: получатель уже мог обработать данные. По умолчанию автоматического повтора неопределённого результата нет; оператор должен проверить получателя перед ручным повтором. Заголовок идемпотентности помогает избежать дубликатов только если получатель сам его поддерживает.
